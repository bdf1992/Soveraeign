# sov-compression

## Purpose

Make repeated learning cheaper than repeated reconciliation.

This is a harness procedure, not a semantic owner. Read and obey the owning
skills instead of copying their rules:

- `.claude/skills/sdlc-feedback/SKILL.md` — learning routes, cadence, gap terminal,
  skill-extraction rule;
- `.claude/skills/sov-governance/SKILL.md` — authoritative producer, phase/gap
  boundary, owner-decision routing;
- `.claude/skills/sov-verification/SKILL.md` — observation correlation and gate
  cards.

If these disagree, the owning governing documents and contracts they cite win.

## Operating invariants

1. Historical Phase I remains `CLOSED_INCOMPLETE`; this ritual cannot reopen it.
2. No successor phase exists until the root seat opens one explicitly.
3. One authoritative producer may have many readers and independent observers.
4. Correlate repeated observations before creating repeated work.
5. Useful independent corroboration is preserved; redundant recomputation is a
   compression target.
6. Reports observe, lessons generalize, decisions change policy, concerns create
   work. Do not collapse the four.
7. A lesson claiming `EFFECTIVE` must have the executable carrier the lessons
   contract requires.
8. A blocking gate must be explainable by risk, scope, test, pass criterion,
   evidence class, expected cost, and owner. No criterion means advisory unless a
   governing rule already says otherwise.
9. Close before widening. Prefer removing, deriving, correlating, settling, or
   narrowing a surface over adding another representation.
10. `GAP_OPERATIONALLY_INVISIBLE` is a readiness reading, not phase opening or
    acceptance.

## Daily procedure

Run `sov-compression` with `cadence: "daily"`.

Read the delta, not the whole project as if nothing was learned yesterday. Return:
new findings, repeated/correlated findings, compressions available now, lesson
movement, owner decisions that materially gate the proving/opening path, the
smallest next settlement/compression operation, and the fresh-reader gap reading.

Do not create work merely because the ritual needs an output.

## Weekly procedure

Run `sov-compression` with `cadence: "weekly"`.

Treat the week as one system. Find repeated defect shapes, duplicate truth
producers, redundant observation, stale derived views, unjustified gate cost,
procedures that may now deserve skill extraction, closure/opening imbalance, and
representations that can disappear or become derived.

Report control signals only when their denominator is actually available. Use
`UNMEASURED` rather than inventing a number.

## Terminal

The gap is operationally invisible only when an independent fresh-reader pass can
reach current state and the progressive participant path without oral history,
EFFECTIVE lessons have real carriers, material owner decisions are attached only
to the transitions they gate, and surviving work is ordinary readiness rather
than historical archaeology or reconciliation.

At that point report `GAP_OPERATIONALLY_INVISIBLE` and stop minting gap work.
The daily ritual may continue as regression detection and the weekly ritual may
continue as system compression, but neither should preserve a gap that is no
longer observable.

## Effect and standing

The skill is observe-oriented harness plumbing. Running it spends resources but
creates no product standing or authority. A report from it is executor/model
output until independently checked where standing would consume it.
