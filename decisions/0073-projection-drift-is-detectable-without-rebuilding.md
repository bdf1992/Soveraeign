# 0073 · Projection drift is detectable without rebuilding

Status: `PROPOSED · BUILT AND SELF-TESTED · RATIFICATION PENDING`

## Decision

The Asset Service declares `read-projection-drift`
(`sov://asset/read-projection-drift`, `READ`/`DERIVED`), answered at
`BACK`/`inspectorate` under `read:projection`. It names every projected row that
disagrees with the ledger and writes nothing: not to the projections, and not a
receipt.

`projections.derived` becomes the single derivation both callers use. `rebuild`
stores what it returns; `drift` compares against it. Neither can hold a private
idea of what the ledger implies, because there is only one implementation of
implying it.

## What defeated the previous arrangement

`test_projection_authority.py` already proved the property that matters about
projections: a row forged straight into one does not survive a rebuild. What was
missing beside it was any way to *ask* whether a view currently matches the
ledger. The only answer available was to rebuild, which destroys the evidence in
the act of collecting it, so callers compared row counts instead — the console
workspace binding does exactly this today.

A count is structurally blind to the failure that matters. Rewriting a projected
row in place moves no count:

    assets = 2, search_projection = 2      -> the count check says "in step"
    UPDATE search_projection SET text_value = 'Totally Different Thing' ...
    assets = 2, search_projection = 2      -> the count check still says "in step"

    search("Totally Different")  -> ['asset_57dfd479...']
    search("Campaign Hero")      -> []

The view now answers for a label that was never ingested, and refuses the one
that was. `drift` reports `PROJECTION_ALTERED` for that row; the count check
reports nothing, before and after.

Three disagreements are named separately because they have different causes:
`PROJECTION_BEHIND` (the ledger implies a row the view omits),
`PROJECTION_UNSOURCED` (the view carries a row no ratified record supports), and
`PROJECTION_ALTERED` (the stored row differs from the derived one).

## Defaults taken

- **Detection and repair stay separate.** `drift` reports and returns; `rebuild`
  is still the only writer. A check that repaired what it found would make the
  next reading of it meaningless, and a caller cannot then choose to investigate
  before overwriting the evidence.
- **`drift` writes no receipt.** It is a read over state the caller already
  holds. `test_drift_writes_nothing_at_all` pins both halves — no receipt, and
  the forged row still present afterwards.
- **`BACK`/`inspectorate` under `read:projection`**, matching
  `asset.read-library-conformance`, the other inspectorate read that judges
  derived state against the records behind it. `rebuild-projection` stays at
  `BACK`/`record` under `rebuild:projection`, because it writes.
- **The read surface split out of `core.py`.** Declaring the operation took that
  module to 308 lines against a 300-line limit. The alternative was shortening a
  docstring until the file fitted, which leaves the next addition in the same
  position with less explanation. `reads.ReadSurface` now holds the delegations
  that answer without writing; `rebuild_projections` and `federation_cross`
  stayed in `core.py` because they write.

## Consequences

- The console workspace binding's staleness note can compare content rather than
  counts. That is a separate concern in a separate service and is not done here.
- Adding an operation moved five generated artifacts: the capability map, the
  Node Interface projection, the surface page, the docs reader, and the
  JOURNEY-02 measured receipt. The receipt was regenerated by re-running the
  crossing, not by editing its `input_state_digest`, because a receipt edited to
  agree with a test is no longer a measurement.
- `scripts/tests/test_node_interface.py` repins 133/45 to 134/46. `CLAUDE.md` on
  `main` still reads 102 declared operations; it was stale by 32 before this
  change and is left alone rather than half-corrected inside an unrelated
  concern.

## What would defeat this

- A disagreement `drift` reports that a rebuild does not then clear.
  `test_rebuilding_is_what_clears_drift` fails if the two derivations disagree.
- Any write performed by `drift`. Pinned by `test_drift_writes_nothing_at_all`.
- A projection failure mode outside the three named defects. That would mean the
  vocabulary is incomplete rather than wrong, and the fix is a fourth name.

## Standing

`PROPOSED`. Built and self-tested: 146 Asset Service tests pass, 8 of them new.
Self-tests establish `BUILT` and nothing here has been independently observed.
Only Bdo ratifies.
