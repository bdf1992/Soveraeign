## Goal

Bdo asked to start building a session-based interface surfacing user notifications, user settings,
admin dashboards, human-in-and-on-the-loop workflows, and distributed activity reporting, with a
threaded, domain-driven feel (Claude/ChatGPT work) and Discord/Slack social interaction.

## The read

The repository forbids runtime code before a logical spec and defeating fixtures, and admits no
binding implementation before the transition contract is frozen or Bdo authorizes a provisional
target. So the interface landed as what it is underneath: a third sibling service boundary, the
**Console Service**, whose records are what the threaded UI (a Human Binding) and a model operator
(a Model Binding) both read and write through the kernel. Each of the five surfaces maps to an
existing Phase-I requirement rather than new policy: threads are the PROD-I-3 crossing, judgement
requests are PROD-I-6 queued without blocking, the activity view plus kernel retraction is
PROD-I-4 human-on-the-loop, dashboards are SPEC.md projections, and settings are records that can
never widen an authority check (C3).

The set is BUILT and verify-green. The witness stopped short of WITNESSED on two fixture coverage
limbs and one stale paragraph, all three fixed after the observation; a re-witness is the next
bounded operation. Nothing can move past that until Bdo rules O14.

## Residuals

1. No fixture exercises `ON_LOOP`, `WITHDRAWN`, `EXPIRED`, notification kinds `ASSIGNMENT` /
   `JUDGEMENT_REQUESTED` / `RECEIPT_OUTCOME`, or operations `open-session`, `close-session`,
   `open-channel`, `open-thread`, `request-judgement`. Charter narrative steps 1, 2, 12 are unfixtured.
2. The charter does not say what happens to an `UNRESOLVED` conditioned operation when its
   judgement request expires or is withdrawn.
3. `console-receipt` is owned in the manifest with no schema; it must stay the kernel `Receipt`
   shape, never a second contract.
4. `scripts/lint.py` reads with `Path.read_text`, so its CRLF check never fires; CRLF from the
   Write/Edit tools passed lint during this run and was caught only by byte count. Verification
   domain; not changed here.
5. Vocabulary introduced without a per-term proposal mark: `projection-view.kind`,
   `operator-setting.holder_kind`, `notification.delivery`, four notification kinds;
   `notification.kind: COUNTERED` reuses an event-outcome term in a different role.
6. Schema style fork: console schemas list nullable fields in `required` (kernel envelope style);
   proofing-session leaves them optional.
