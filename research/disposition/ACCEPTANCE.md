# Disposition Lab v0.1 acceptance packet

Status: `RESEARCH CANDIDATE · ISSUE #200`

This packet defines what the first scaffold must demonstrate before the experiment is treated as ready for data collection.

## Required

- skill exists and states the evidence/construct/profile/projection separation;
- local evidence persistence is append-only and verifiable;
- profile derivation is deterministic;
- reports are rebuildable projections;
- model/agent subject revisions require material configuration;
- missing evidence, unknown constructs, and out-of-range scores refuse;
- fewer than three observations remain explicitly insufficient for a construct estimate;
- unvalidated named-framework projections require explicit opt-in;
- cross-adapter/cross-kind comparison defaults to `NOT_COMPARABLE`;
- research plan distinguishes software verification from psychometric validation;
- first experiment can test equivalent semantic probes without requiring anthropomorphic role-play.

## Explicitly not required for scaffold acceptance

- validated eight-factor structure;
- calibrated item-response parameters;
- population norms;
- validated Big Five/HEXACO/MBTI/CVI crosswalks;
- adaptive probe selection;
- production Record Service integration;
- user-facing Console UI;
- reception/vibe scoring;
- successor-phase opening.

## Defeating outcomes

The scaffold should not be accepted if:

- modifying a recorded observation can pass ledger verification;
- regenerated profiles differ under identical evidence and definition revisions;
- an unvalidated projection can appear without its standing/loss disclosure;
- a model profile can omit the configuration needed to reproduce the behavior;
- the implementation implies that local research storage supersedes the Record Service;
- framework labels are used as canonical construct identities;
- comparison across subject kinds is possible without explicit equivalence evidence.
